# 로컬 실행 명령어

모든 명령은 저장소 루트(`MCP_Capstone/`)에서 실행한다.

## 처음부터 전부 켜기

1. Docker Desktop 켜기
2. `docker compose up -d postgres`
3. `scripts/run_all.sh`
4. (새 터미널) `uv run python -m apps.slack_bot`
5. (새 터미널, 외부 공개가 필요할 때) `scripts/tunnel.sh` → 고정 주소 https://nodi-admin.chltmddn5843.workers.dev

## 외부 공개 (고정 주소)

- 화면은 Cloudflare Workers(`apps/admin_web/wrangler.jsonc`)가 낸다. GitHub main에 push하면 Workers Builds가 자동으로 빌드·배포한다.
- `/api/*`는 Worker(`apps/admin_web/worker.js`)가 로컬 서버로 넘긴다. 로컬은 Quick Tunnel이라 주소가 매번 바뀌므로 `scripts/tunnel.sh`가 새 주소를 KV에 적는다 (반영까지 최대 1분).
- 로컬 서버나 터널이 꺼져 있으면 고정 주소는 화면만 뜨고 API는 503을 낸다.
- 수동 배포: `cd apps/admin_web && npm run build && npx wrangler deploy`

## 1. DB (Postgres)

```bash
docker compose up -d postgres                    # DB 켜기 (Docker Desktop 필요)
docker compose ps                                # 127.0.0.1:5432->5432 매핑이 보여야 정상
docker compose up -d --force-recreate postgres   # 포트 매핑이 빠졌을 때 재생성 (데이터 유지)
db/reset.sh                                      # 스키마·시드 초기화 (데이터 삭제됨)
```

## 2. 서버 (백엔드 · MCP · 에이전트 · 관리자 화면)

```bash
scripts/run_all.sh                          # 한 번에 켜기. 같은 터미널에서 Ctrl+C로 전부 종료
MCP=0 scripts/run_all.sh                    # MCP 서버 없이 (에이전트가 백엔드 REST 직접 호출)
pkill -f 'uvicorn apps\.|apps\.mcp_|vite'   # 다른 터미널에서 끌 때
```

- `.env`를 바꾸면 끄고 다시 켜야 반영된다.
- 화면 http://localhost:5173 · 백엔드 http://localhost:8000/docs · 에이전트 http://localhost:8002/docs

## 3. Slack 봇 (`run_all.sh`에 포함되지 않음)

```bash
uv run python -m apps.slack_bot --check    # 토큰·scope·채널·매핑 점검
uv run python -m apps.slack_bot            # 봇 실행 (2번 서버가 떠 있어야 함)
uv run python -m apps.slack_bot --run-f1   # F1 자동 제안 한 바퀴만 돌리고 종료 (시연용)
pkill -f apps.slack_bot                    # 봇 끄기
```

- `.env`의 Slack 값을 바꾸면 봇도 재시작한다.

## 4. 외부 공개 (Cloudflare quick tunnel)

```bash
cloudflared tunnel --url http://localhost:5173   # 출력의 https://xxxx.trycloudflare.com 이 외부 주소
```

- 켤 때마다 주소가 바뀐다. `vite.config.js`의 `allowedHosts`가 `.trycloudflare.com` 전체를 허용하므로 설정은 그대로 둔다.
- 서버만 재시작할 때는 터널을 끄지 않아도 된다.

## 5. 로그

```bash
tail -f logs/backend.log     # 백엔드
tail -f logs/agent.log       # 에이전트 (LLM·API 키 오류는 여기)
tail -f logs/admin_web.log   # 화면 (vite)
tail -f logs/mcp_work.log    # 업무 MCP (문서 MCP: logs/mcp_docs.log)
```

## 자주 나는 문제

| 증상 | 원인 · 해결 |
| --- | --- |
| 로그인 시 `OperationalError ... port 5432` | DB가 꺼져 있거나 포트 매핑 누락 → 1번 명령 |
| Slack에 아무 반응 없음 | 봇 미실행 → 3번 명령 |
| Slack 답변이 "처리 중 문제가 생겼어요" | 에이전트 실패. `logs/agent.log` 확인. 흔한 원인은 `LLM_MODEL`의 공급사 키가 `.env`에 없거나, 셸(`~/.zshrc`)에 `export`된 예전 키가 `.env` 값을 덮어씀 (`load_dotenv`는 이미 있는 환경변수를 덮어쓰지 않는다) |
| Slack 요청 이력 확인 | PostgreSQL `agent.tasks` (DBeaver에서 `body->>'status'`, `body->>'input'`) |
| 터널 주소로 접속 시 "Blocked request" | `vite.config.js`의 `allowedHosts` 확인 |
