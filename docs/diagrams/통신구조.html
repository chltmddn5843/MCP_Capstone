통신

전체 통신 체계

사용자는 화면만 보고, 화면은 backend 하나만 부릅니다. AI 판단은 agent가, 데이터 읽기·쓰기 규칙은 backend가 맡습니다. 원 번호는 질문 하나가 처리되는 순서입니다.

경로

요청이 흐르는 세 가지 경로

걸리는 시간에 따라 길을 나눴습니다. 조회·등록은 바로 답하고, AI 질문은 접수 후 진행 상황을 실시간으로 보내며, 수집·발송·실행은 큐에 넣어 실패해도 다시 시도합니다.

F1 · AI 활용 지원 · 자동

업데이트 기반 직무별 활용 제안

사용자관리자(기록 확인), 직원(제안 수신)
웹에서 하는 일관리자는 '자동 제안 기록' 탭에서 업데이트별로 어느 팀에 무엇을 보냈고 왜 보내지 않았는지 보고, 팀별 자동 발송을 켜고 끈다. 직원은 Slack으로 받은 제안에 '도움 됨 / 관련 없음 / 질문'으로 반응한다.
받는 결과직원용 Slack 제안(원문 링크·활용 예시), 판단 기록 표

기획 확인 사항

  • 사람 승인 없이 자동 발송한다. 대신 팀당 주 2건, 평일 09~18시, 관련 근거 필수 규칙을 코드로 검사한다.
  • 회사 플랜에 없는 기능이거나 관련 업무 근거가 없으면 보내지 않고 보류 사유를 남긴다.
  • 같은 분야에 '관련 없음'이 2번 연속이면 그 팀에는 4주간 보내지 않는다.
F2 · AI 활용 지원 · 대화

업무별 모델 선택 지원

사용자직원
웹에서 하는 일직원이 'AI 비서'에 업무를 설명한다(예: 하루 1,000건 문의를 10개 유형으로 분류, 비용 줄이기). 진행 상황이 실시간으로 보이고, 추천 모델과 근거, 예상 월 비용을 받는다. 원하면 테스트 적용을 요청한다.
받는 결과추천 모델, 선정 근거, 예상 비용, 품질 조건, 테스트 적용 요청

기획 확인 사항

  • 건수·입력 길이·품질 기준·응답 시간 중 빠진 조건이 있으면 한 번에 묻고 답을 기다린다.
  • 사전 평가 결과가 없는 모델은 추천하지 않고 '평가 필요'라고 답한다.
  • AI가 필요 없는 업무(예: PDF 편집)는 승인된 일반 소프트웨어를 안내한다.
  • 모델 변경은 바로 바뀌지 않고 관리자 승인 대기로 간다.
F3 · AI 운영 지원

사용량 · 비용 모니터링

사용자관리자
웹에서 하는 일관리자가 '비용 경보' 탭에서 프로젝트별 사용 추이와 경고를 본다. 경고를 열면 에이전트가 미리 조사한 원인 후보(요청량·사용 모델·입력 길이)와 근거가 보이고, 대응안 하나를 고르면 처리 요청이 만들어진다.
받는 결과사용 추이, 경고 표시, 상세 현황, 원인 후보, 대응 검토안

기획 확인 사항

  • 사용량은 10~30분마다 수집하고, 기준치의 3배를 넘으면 경고를 만든다.
  • 원인은 후보로만 제시하고 단정하지 않는다.
  • 벤더 API가 일시적으로 실패해도 큐가 재시도하므로 수집이 빠지지 않는다.
F4 · 소프트웨어 운영 지원

자산 현황 · 이용권 운영

사용자직원(신청·사용 의사 응답), 관리자(현황·승인)
웹에서 하는 일직원이 'AI-A 이용권 주세요'라고 신청한다. 남은 좌석이 있으면 바로 쓸 수 있고, 없으면 관리자 '승인함'에 AI 의견과 함께 올라간다. 관리자는 '이용권' 탭에서 계약 수량, 배정·미배정, 저사용 현황을 본다.
받는 결과자산 목록, 이용권 현황, 사용 의사 확인, 배정·재배분 검토안, 처리 이력

기획 확인 사항

  • 남은 좌석이 있으면 사람 승인 없이 즉시 배정하고 기록만 남긴다.
  • 회수·재배정은 대상자의 사용 의사 확인 응답이 있어야 실행한다. 무응답은 회수 사유가 아니다.
  • 사용 기록이 없으면 '미사용'이 아니라 '확인 필요'로 표시한다.
  • 같은 배정을 두 번 실행해도 결과가 같다(중복 배정 방지).

화면이 받는 진행 이벤트

AI 질문은 답이 나올 때까지 수 초에서 수십 초가 걸립니다. 그동안 화면은 아래 이벤트를 받아 상태를 보여줍니다.

이벤트언제화면 표현
TOKEN답변이 만들어지는 동안답변 영역에 글자가 이어 붙는다
TOOL_START · TOOL_END데이터 조회 전후'이용권 현황 조회 중…' 같은 상태 표시
APPROVAL_REQUIRED데이터를 바꾸기 직전 멈췄을 때승인 카드 (무엇을, 누구에게, 근거)
DONE · FAILED작업이 끝났을 때결과 확정, 작업 목록 갱신
