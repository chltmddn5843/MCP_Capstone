# 아키텍처 설계 v3 — 레퍼런스 정렬 · 대기열 · 배포

2026-10-21 · 작성 백엔드+DB · 상태 **제안 (리드 리뷰 필요)**
그림: `docs/architecture.drawio` (1 시스템 구성도 · 2 배포 · 3 큐 처리·재시도). draw.io에서 파일 → 열기.

기능·시나리오는 `docs/설계문서.md` v2를 그대로 따른다. 이 문서는 **구조·프레임워크·API·장애 관리·배포**만 다룬다.

## 1. 목표와 원칙

| 목표 | 확인 방법 |
| --- | --- |
| 기능을 우리가 직접 점검할 수 있다 | `uv run pytest` + 서비스별 `/healthz` + 시연 스크립트 |
| API가 계약으로 고정된다 | `packages/schemas` → `specs/*.json`, 계약 테스트 |
| 서버가 죽거나 느려도 데이터가 안 깨진다 | 재시도·멱등키·DLQ·healthcheck (6절) |
| `docker compose up` 한 줄로 웹까지 뜬다 | `docker-compose.yml` (7절) |

원칙은 강의 레퍼런스(표 5-1)를 우리 스택에 맞춘 것이다.

1. 업무 규칙과 데이터 변경은 **backend 한 곳**. MCP·에이전트·워커는 DB에 직접 쓰지 않는다(체크포인터 제외).
2. LLM 요청은 **202 + SSE**. 화면은 에이전트 주소를 모른다.
3. 공개 포트는 **admin_ui, backend 둘뿐**. 나머지는 docker network 안.
4. 오래 걸리거나 외부를 부르는 백그라운드 일은 **RabbitMQ 큐**로, 실패하면 재시도한다.

## 2. 레퍼런스와 우리 구조 대응

| 레퍼런스 (강의) | 우리 | 현재 상태 | v3 변경 |
| --- | --- | --- | --- |
| Vue 3 | admin_ui (Streamlit) | 동작 | 에이전트 직접 호출 → **backend `/ai/tasks` 경유** (`common.py`의 `AGENT` 주소만 교체) |
| Spring Boot | backend (FastAPI) | 고정 데이터 스텁 | **PostgreSQL 전환, JWT, `/ai/tasks` 중계, 작업 발행** |
| FastAPI Agent | agent_runtime | 동작 | checkpointer를 Postgres로 (리드) |
| business-mcp | mcp_work | 동작 (backend REST 호출) | 변경 없음 |
| rag-mcp | mcp_docs | FTS5 검색, Resource 없음 | **문서 원문 Resource 1개 추가** (강의 3절 필수), 벡터는 선택 |
| PostgreSQL 16 | postgres | 없음 (SQLite·메모리) | 신규 |
| Vector DB | (선택) pgvector | FTS5 | 같은 postgres 이미지(`pgvector/pgvector:pg16`)로 여지만 둔다 |
| — (가산점) | rabbitmq + worker + beat | 없음 | 신규 |

> **의도된 차이**: 레퍼런스는 business-mcp가 `/internal/**`를 부르지만, 우리는 **요청자 JWT를 그대로 넘겨 공개 API를 부른다**. 권한 검사가 backend 한 곳에서 같은 규칙으로 일어나므로 규칙 복제가 없고, 내부 전용 경로를 따로 지킬 필요도 없다. `/internal/**`은 배치 트리거처럼 사람이 부르지 않는 경로에만 쓴다.

## 3. 프레임워크 선택

| 계층 | 선택 | 버전 | 고른 이유 / 대안 |
| --- | --- | --- | --- |
| 화면 | Streamlit | ≥1.38 | 이미 동작. Vue 전환은 일정상 이득 없음 |
| API 서버 | FastAPI + Uvicorn | ≥0.115 | 기존 코드, Pydantic 스키마와 직결 |
| ORM·마이그레이션 | **SQLAlchemy 2.0 + Alembic** | 2.0 / 1.13 | 공유 스키마(리드 소유)와 ORM을 분리. SQLModel은 경계가 섞여 제외 |
| DB | **PostgreSQL 16** | 16 | 백엔드·워커·체크포인터 동시 쓰기. SQLite는 잠금 충돌 |
| 인증 | **PyJWT + bcrypt** | 2.x | `current_user()` 하나만 교체. Keycloak·OAuth는 일정에 과함 |
| 대기열 | **RabbitMQ + Celery** | 3.13 / 5.4 | 재시도·백오프·스케줄(beat)이 내장. Kafka는 로그 스트림용이라 과함 |
| 에이전트 | LangGraph + langgraph-checkpoint-postgres | 1.x | 레퍼런스 그대로 |
| MCP | FastMCP (Streamable HTTP) | 4.1 | 레퍼런스 그대로 |
| 배포 | Docker Compose | v2 | 강의 배포 구성(표 5-10) |

새로 추가하는 의존성: `sqlalchemy`, `alembic`, `psycopg[binary]`, `pyjwt`, `bcrypt`, `celery`, `langgraph-checkpoint-postgres`.
APScheduler는 Celery beat가 대신하므로 넣지 않는다.

## 4. 서비스와 폴더 구조

```
apps/
  backend/
    main.py            FastAPI 앱 조립 (라우터 include, 오류 핸들러, /healthz)
    auth.py            JWT 발급·검증, require(role)   ← current_user만 교체
    db.py              엔진·세션 (DATABASE_URL)
    models.py          SQLAlchemy 테이블 (enum은 schemas.common 값 그대로)
    routers/           기존 라우트를 도메인별로 분리: me, catalog, f1, f2, f3, f4, plans, audit, ai_tasks, jobs
    services/          알림 정책, 승인 상태머신, 좌석 배정 (규칙은 여기 한 곳)
    jobs/              Celery 앱 + 태스크 (collect_usage, check_thresholds, collect_release_notes,
                       send_suggestion, execute_plan, run_system_agent)
    adapters/          VendorAdapter Protocol + mock 구현 (httpx)
  mock_vendor/main.py  AI-A·AI-B·Adobe Mock API, ?fail_rate= 장애 주입
db/
  migrations/          Alembic
  seed/seed.py         fixtures.py id를 그대로 넣는 시드 (계약 테스트 유지)
docker/                서비스별 Dockerfile 1개 공용 (python:3.12-slim + uv)
docker-compose.yml
```

worker·beat는 **backend와 같은 코드**를 다른 명령으로 띄운다(`celery -A apps.backend.jobs worker|beat`). 새 서비스 코드를 따로 만들지 않는다.

## 5. API 설계

### 5-1. 공통 규약 (이미 있음, 유지)
- 성공 `{"data": …, "meta": {"request_id"}}`, 오류 `{"error": {"code", "message", "details"}}` — `apps/backend/errors.py`
- 오류 코드 ↔ HTTP 상태는 `schemas.common.HTTP_STATUS_BY_CODE` 하나에서 관리
- 모든 요청은 `Authorization: Bearer <JWT>`, `X-Trace-Id`(없으면 backend가 발급)를 서비스 사이에 그대로 전달

### 5-2. 인증
| Method | Path | 설명 |
| --- | --- | --- |
| POST | `/auth/login` | 사번+비밀번호 → `{access_token, expires_in}` (HS256, 1시간, claim: `sub`, `role`) |
| POST | `/auth/dev-login` | 개발용. `APP_ENV=dev`일 때만 열림 |
| GET | `/me` | 토큰 주인. MCP가 역할 확인에 쓴다 (변경 없음) |

시스템 계정(배치·워커)은 `SYSTEM_TOKEN`을 서명된 JWT(`role=system`)로 발급해 환경변수로 주입한다.

### 5-3. AI 작업 중계 (신규, 레퍼런스 표 5-8)
| Method | Path | backend가 하는 일 |
| --- | --- | --- |
| POST | `/ai/tasks` | 권한 확인 → agent `POST /ai/tasks` 전달 → 202 `{task_id}` |
| GET | `/ai/tasks/{id}` | agent 결과 조회 전달 |
| GET | `/ai/tasks/{id}/stream` | agent SSE를 그대로 흘려보냄 (`httpx` 스트리밍, `?after=` 유지) |
| POST | `/ai/tasks/{id}/approval` | 관리자 권한 확인 후 전달 → 202 |
| GET | `/ai/tasks?mine=true` | 전달 |

에이전트가 응답하지 않으면 `503 {"error":{"code":"agent_unavailable"}}`. 경로와 이벤트 형식은 `schemas/agent.py` 그대로라 화면은 주소만 바꾼다.

### 5-4. 업무 API
기존 라우트(`/plans`, `/inventory`, `/usage`, `/anomalies`, `/suggestions`, `/confirmations`, …)와 `response_model`은 **그대로** 둔다(계약 테스트). 내부만 고정 데이터 → DB 조회로 바꾼다.

### 5-5. 운영 API (신규)
| Method | Path | 역할 | 설명 |
| --- | --- | --- | --- |
| GET | `/healthz` | 없음 | DB·RabbitMQ 연결 확인. compose healthcheck가 부른다 |
| POST | `/internal/jobs/{name}/run` | admin, system | 배치를 큐에 넣는다 → 202 `{job_id}` (지금은 동기 실행) |
| GET | `/internal/jobs?status=dead` | admin | 실패 작업 목록 |
| POST | `/internal/jobs/{id}/retry` | admin | DLQ 작업 수동 재실행 |

## 6. 데이터

한 PostgreSQL 인스턴스, 스키마 둘.

| 스키마 | 소유 | 테이블 |
| --- | --- | --- |
| `app` | backend | 설계문서 6절 테이블 + **`job_runs`**(id, name, status, attempt, idempotency_key UNIQUE, last_error, trace_id, created_at, finished_at) |
| `agent` | agent_runtime | LangGraph checkpoint 테이블, 작업·이벤트 이력 |

무결성은 DB 제약으로 막는다.
- `seat_assignments (contract_id, employee_id)` UNIQUE → 재시도해도 이중 배정 없음
- `action_plans` 상태 전이는 `UPDATE … WHERE status = :expected` 로만 (원칙 4: 실행 직전 재확인)
- `job_runs.idempotency_key` UNIQUE → 같은 작업 중복 발행 차단

## 7. 대기열 (가산점)

| 큐 | 작업 | 누가 넣나 | 재시도 |
| --- | --- | --- | --- |
| `batch` | collect_usage → check_thresholds, collect_release_notes, aggregate_unmet_needs | beat, `/internal/jobs/*/run` | 3회, 10s·30s·90s |
| `agent` | run_system_agent (review_update, investigate_anomaly, review_seat_request) | batch 작업 결과 | 3회. 에이전트 FAILED·503이면 재시도 |
| `notify` | send_suggestion (Slack), confirmation 기한 알림 | 알림 정책 통과 시 | 3회. 업무 시간 밖이면 `eta`로 다음 09:00 예약 |
| `batch` | execute_plan (Mock 벤더 좌석 실행) | 승인된 plan | 3회. `Idempotency-Key`로 중복 실행 없음 |

규칙: 재시도는 **일시 오류만**(연결 실패, 5xx, 429, 타임아웃). 4xx·검증 실패는 바로 `failed`. 3회 실패하면 DLQ(`jobs.dlq`) + `job_runs.status=dead`, 관리자 화면에서 수동 재실행. 흐름은 drawio 3페이지.

## 8. 장애 관리

| 장애 | 감지 | 처리 | 사용자가 보는 것 |
| --- | --- | --- | --- |
| 컨테이너 다운 | compose healthcheck | `restart: unless-stopped`, 의존 서비스는 `service_healthy` 뒤 기동 | 잠시 503 후 복구 |
| LLM 429·503 | Harness Recovery | 2회 재시도 → 대체 모델 → FAILED (기존) | "다시 시도 중" 이벤트, 최종 FAILED |
| 에이전트 다운 | backend 중계 타임아웃 | 503 `agent_unavailable` | 화면에 오류 메시지 |
| MCP 다운 | 에이전트 도구 호출 실패 | ToolMessage로 모델에 전달 (기존) | 답변에 "조회 실패" 명시 |
| 벤더 API 실패 | worker 예외 | 큐 재시도 → DLQ | 관리자 '실패 작업' |
| 같은 요청 두 번 | 멱등키·UNIQUE | 두 번째는 첫 결과 반환 | 변화 없음 |
| DB 연결 끊김 | `pool_pre_ping` | 재연결, 실패 시 500 JSON | 오류 메시지 |
| 추적 | `X-Trace-Id` 전 서비스 전달 | 로그·job_runs·LangSmith에 같은 id | — |

시연은 `mock_vendor ?fail_rate=0.5`로 503을 일부러 내서 재시도 → 성공, 그리고 DLQ까지 보여준다.

## 9. 배포 (docker compose)

| 서비스 | 이미지·명령 | 포트 | 공개 | depends_on (healthy) |
| --- | --- | --- | --- | --- |
| postgres | `pgvector/pgvector:pg16`, volume `pgdata` | 5432 | – | – |
| rabbitmq | `rabbitmq:3.13-management` | 5672 / 15672 | 15672는 127.0.0.1만 | – |
| mock_vendor | app 이미지 `uvicorn apps.mock_vendor.main:app` | 8001 | – | – |
| backend | `alembic upgrade head && uvicorn apps.backend.main:app` | 8000 | ○ | postgres, rabbitmq |
| mcp_work · mcp_docs | `python -m apps.mcp_work.server` 등 | 8010 · 8011 | – | backend |
| agent | `uvicorn apps.agent_runtime.main:app` | 8002 | – | mcp_work, mcp_docs, postgres |
| worker | `celery -A apps.backend.jobs worker -Q batch,agent,notify` | – | – | backend, rabbitmq |
| beat | `celery -A apps.backend.jobs beat` | – | – | rabbitmq |
| admin_ui | `streamlit run apps/admin_ui/app.py` | 8501 | ○ | backend |
| slack_bot | `python -m apps.slack_bot` (토큰 있을 때만, profile `slack`) | – | – | backend |

이미지는 하나(`docker/Dockerfile`, `uv sync --frozen`)로 빌드하고 서비스마다 `command`만 다르게 준다. 비밀값은 `.env`로만 넣는다. 서비스 주소는 compose 서비스 이름(`http://backend:8000`)을 쓴다.

## 11. 점검 체크리스트

| 항목 | 명령 / 방법 | 기대 결과 |
| --- | --- | --- |
| 계약 | `uv run pytest` | 전부 통과 |
| 기동 | `docker compose up -d && docker compose ps` | 전 서비스 `healthy` |
| 인증 | `/auth/login` → 토큰 없이 `/plans` | 401 JSON |
| AI 경로 | 화면에서 질문 → 진행 이벤트 → 답변 | TOKEN·TOOL·DONE 순서 |
| 승인 재개 | 변경 요청 → 승인 카드 → 승인 | 같은 thread로 재개, 감사 로그 1건 |
| 큐 재시도 | `fail_rate=0.5`로 `collect_usage` 실행 | `job_runs.attempt` 증가 후 done |
| DLQ | `fail_rate=1.0` | `dead` 1건, 수동 재실행 후 done |
| 자가 복구 | `docker compose kill agent` | 중계 503 → 재시작 후 정상 |
