[작업: 새 모델 카드 뉴스] update_id={update_id}
목표: 새 모델 출시 업데이트로 전 직원에게 보낼 카드 뉴스 한 장(핵심 기능 3개 + 직무별 활용)을 저장한다. 이 작업은 보류하지 않는다.
A0. get_vendor_update(update_id)로 제목과 요약을 읽는다. 제목 "새 모델 출시: X"의 X가 **이 카드의 모델 이름**이다. 카드의 추천 모델은 항상 X이고 다른 모델(이전 버전, 다른 공급사, 승인 목록의 모델)을 쓰지 않는다. list_approved_models는 부르지 않는다.
승인 공급사 여부는 감지 단계에서 이미 걸렀다. 플랜 일치나 업무 관련성을 이유로 보류하지 말고 반드시 카드를 저장한다. 사내 승인 전·후 표시는 시스템이 보낼 때 붙인다.
A1. find_relevant_tasks(update_id)를 부른다. 결과의 jobs는 등록 업무 수로 센 직무 목록(많은 순)이고 task_titles가 그 직무의 등록 업무다. 직무마다 "X의 핵심 기능이 그 등록 업무를 실제로 바꾸는가"를 보고, 바꾸는 직무만 고른다(최대 6개). 억지로 채우지 않는다. 고를 직무가 하나도 없으면 "• 전 직원: (핵심 기능으로 할 수 있는 일 한 문장) (추천 모델: X)" 한 줄만 쓴다.
A2. save_suggestion(update_id, target_type=all, relevance="승인 공급사 새 모델 X · 직무 N개 활용 예", body=카드)를 **한 번만** 저장한다. body는 아래 형식을 글자 그대로 지킨다(머리글 두 줄, 번호·불릿 기호, 괄호 표기):
   핵심 기능
   1. (한 줄)
   2. (한 줄)
   3. (한 줄)
   이렇게 써 보세요
   • 직무명: 그 직무의 등록 업무에 X를 쓰는 방법 한 문장 (추천 모델: X)
   핵심 기능은 업데이트 요약에 있는 것만 쓰고 지어내지 않는다. 직무명은 job_title을 그대로, 활용 문장은 그 직무의 task_titles를 근거로 쓴다. 모든 직무 줄의 괄호는 정확히 "(추천 모델: X)"이며 X는 A0의 모델 이름이다. 직무 줄 뒤에 다른 문장을 붙이지 않는다. 제품 id·내부 id·도구 이름은 쓰지 않는다.
