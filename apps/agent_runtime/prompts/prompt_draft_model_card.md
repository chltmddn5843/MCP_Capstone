[작업: 새 모델 카드 뉴스] update_id={update_id}
목표: 새 모델 출시 업데이트로 전 직원에게 보낼 카드 뉴스 한 장(핵심 기능 3개 + 직무별 활용)을 저장한다. 이 작업은 보류하지 않는다.
A0. get_vendor_update(update_id)로 요약을 읽는다.
승인 공급사 여부는 감지 단계에서 이미 걸렀다. 플랜 일치나 업무 관련성을 이유로 보류하지 말고 반드시 카드를 저장한다.
A1. find_relevant_tasks(update_id)를 부른다. 결과의 jobs는 시스템이 등록 업무 수로 센 직무 목록(많은 순)이다. 위에서부터 3~6개를 그 순서대로 쓴다.
A2. save_suggestion(update_id, target_type=all, relevance="승인 공급사 새 모델 · 직무 N개 활용 예", body=카드)를 **한 번만** 저장한다. body는 아래 형식 그대로:
   핵심 기능
   1. (한 줄)
   2. (한 줄)
   3. (한 줄)
   이렇게 써 보세요
   • 직무명: 그 직무의 등록 업무에 이 모델을 쓰는 방법 한 문장 (추천 모델: 모델 이름)
   핵심 기능은 업데이트 요약에 있는 것만 쓰고 지어내지 않는다. 직무는 jobs 순서대로 3~6개(jobs가 3개보다 적으면 있는 만큼). 직무명은 job_title을 그대로, 활용 문장은 그 직무의 task_titles를 근거로 쓴다. 추천 모델은 list_approved_models(인자 없이)로 받은 승인 모델 중 그 업무에 맞는 것 하나를 이름으로 쓴다. 새 모델이 아직 승인 전이면 승인 모델 중에서 고르고, 맞는 모델을 판단할 근거가 없으면 "(추천 모델: 확인 필요)"로 쓴다. 제품 id·내부 id·도구 이름은 쓰지 않는다.
