> 제1~6조는 에이전트 쪽 사본(apps/agent_runtime/prompts/policy_ai_usage.md)과 같은 내용이다. 제7~8조는 설계 문서 2절(모델 추천 기준)과 11절(개인정보)을 옮긴 것이다.

## 제1조 허용 도구
승인 도구 카탈로그에 approved로 등록된 도구만 업무에 쓴다.
검토 중(under_review) 도구는 개인 테스트만 허용하고 사내 데이터를 넣지 않는다.

## 제2조 데이터 등급
공개(public) 자료는 모든 승인 도구에, 내부(internal) 자료는 allowed_data_class가 internal 이상인 도구에만 넣는다.
고객 개인정보와 기밀(confidential) 자료는 어떤 외부 AI에도 넣지 않는다.

## 제3조 결과 책임
AI가 만든 결과물은 담당자가 확인한 뒤 사용한다. 외부 발송 문서는 반드시 사람이 검토한다.

## 제4조 활용 지원 데이터
활용 제안 반응과 봇 요청 기록은 교육과 도구 개선에만 쓰고 인사평가에 쓰지 않는다.
HRD는 팀 단위(5명 이상)로만 본다.

## 제5조 이용권 회수
이용권은 업무 필요에 따라 신청·배정한다. 미배정 좌석이 있으면 먼저 배정한다.
마지막 사용일만으로 회수하지 않는다. 사용 기록이 없으면 '미사용'이 아니라 '확인 필요'로 보고 본인에게 사용 의사를 묻는다.
반납 응답이 있을 때만 회수·재배정한다. 무응답은 회수 사유가 아니다. 휴직자와 최근 입사자는 따로 표시한다.

## 제6조 비용과 예산
API 프로젝트는 월 예산을 두고, 일 비용이 평소의 3배를 넘는 등 임계치를 넘으면 자산관리 담당이 원인을 조사한다.
예산 증액은 사용 목적을 확인한 뒤 검토한다. 조치는 승인 뒤 실행한다.

## 제7조 모델 선택
API 업무는 해당 업무의 품질 기준을 통과한 모델 중 예상 처리 비용이 낮은 모델을 쓴다. 평가 결과가 없으면 추천하지 않고 평가를 먼저 한다.
토큰 수 감소와 비용 감소는 구분한다. 정액 좌석제 도구는 모델을 바꿔도 청구액이 바뀌지 않는다.
좌석료와 사용량을 따로 받는 플랜에서는 채팅 사용자의 모델 선택도 비용에 영향을 준다.

## 제8조 개인정보
벤더의 대화 내용 API는 연동하지 않으며, 대화 원문을 수집하지 않는다.
봇 대화는 원문 대신 주제 태그와 요약만 90일 보관하고, 직원이 볼 수 있다.
직원이 등록한 업무는 본인이 직접 보고 고치고 지울 수 있다.
